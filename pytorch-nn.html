בניית רשת ואימון ב-PyTorch

autograd נותן את הנגזרות. כדי לאמן רשת אמיתית צריך עוד חמישה חלקים: מודל (nn.Module), פונקציית Loss, אופטימייזר, צינור נתונים (Dataset ו-DataLoader), ולולאה שמחברת את כולם. אלה בדיוק ארבעת הרכיבים של מודל הלמידה מהפרק הראשון, הפעם כקוד.

מודל משלך: nn.Module

כל רשת היא מחלקה שיורשת מ-nn.Module. ב-__init__ מגדירים את השכבות, וב-forward כותבים איך הקלט זורם דרכן. השכבות שמוגדרות כ-self.something נרשמות אוטומטית, והמשקולות שלהן יופיעו ב-model.parameters().

1import torch.nn as nn2class LinearModel(nn.Module):3def __init__(self, in_features, out_features):4super().__init__()5self.fc = nn.Linear(in_features, out_features)6def forward(self, x):7return self.fc(x)8​9model = LinearModel(10, 2)10out = model(x)        # not model.forward(x)

קוראים ל-model(x) ולא ל-model.forward(x), כי הקריאה דרך __call__ מפעילה גם hooks ועטיפות שהספרייה צריכה.

שכבה לינארית: nn.Linear

זה בדיוק הנוירון שבנינו ממאפס, רק עם הרבה נוירונים במקביל. השכבה מחשבת:

y = x Wᵀ + b
1layer = nn.Linear(in_features=4, out_features=2)2x = torch.randn(3, 4)      # 3 examples, 4 features each3layer(x).shape             # torch.Size([3, 2])4layer.weight.shape         # torch.Size([2, 4])   [out, in]5layer.bias.shape           # torch.Size([2])

מלכודת מבחן: הצורה של המשקולות

המטריצה weight שמורה בצורה [out_features, in_features], כלומר הפוך מהסדר שבו כותבים את השכבה. בגלל זה בנוסחה מופיע Wᵀ. בפרק 8 התכונות כתבנו X @ w עם w בצורה (8, 1). ב-nn.Linear אותן משקולות יישמרו בצורה (1, 8).

פונקציות הפעלה

שכבהמה עושה
nn.ReLU״המדרגה המתוחכמת״: max(0, z). ברירת המחדל לשכבות נסתרות
nn.GELUגרסה חלקה של ReLU. היא הסטנדרט בטרנספורמרים כמו BERT ו-GPT
nn.Sigmoidדוחסת לטווח (0, 1), לסיווג בינארי
nn.Softmaxהופכת וקטור של ציונים להתפלגות הסתברויות על כמה מחלקות

GELU מכפילה את הקלט בהסתברות שמשתנה נורמלי סטנדרטי X יהיה קטן ממנו:

GELU(x) = x · P(X ≤ x)

חיבור שכבות: nn.Sequential

כשהמידע רק זורם קדימה, שכבה אחרי שכבה, אין צורך לכתוב מחלקה. nn.Sequential מחבר את השכבות לפי הסדר:

1mlp = nn.Sequential(2nn.Linear(784, 128),   # fully connected: 784 inputs, 128 neurons3nn.ReLU(),4nn.Dropout(p=0.2),5nn.Linear(128, 10),    # 10 outputs, one per class6)7mlp(torch.randn(32, 784)).shape     # torch.Size([32, 10])8sum(p.numel() for p in mlp.parameters())   # 101770

784 הוא מספר הפיקסלים בתמונה של 28×28, למשל ספרה בכתב יד, ו-10 הוא מספר הספרות. ספירת הפרמטרים, משקולות ועוד bias בכל שכבה לינארית:

784·128 + 128 = 100,480
128·10 + 10 = 1,290
100,480 + 1,290 = 101,770

ל-ReLU ול-Dropout אין פרמטרים. כשצריך חיבורים שמדלגים על שכבה (skip connections), כותבים מחלקה של nn.Module במקום Sequential.

שכבות לתמונות: קונבולוציה, Pooling ו-BatchNorm

שכבת קונבולוציה מחליקה ״חלון״ קטן (kernel) על התמונה ומחפשת בו תבנית, למשל קצה או פינה. אותו kernel משמש בכל מקום בתמונה, ולכן יש לה מעט מאוד פרמטרים. נלמד אותה לעומק בהמשך הקורס. כרגע חשוב לדעת לחשב את גודל הפלט:

H_out = ⌊(H_in + 2P − K) / S⌋ + 1

כאן K הוא גודל ה-kernel, P הוא הריפוד (padding) ו-S הוא גודל הצעד (stride). בדוגמה מהשקף:

conv = nn.Conv2d(in_channels=3, out_channels=16, kernel_size=3, stride=1, padding=1)x = torch.randn(8, 3, 32, 32)conv(x).shape      # torch.Size([8, 16, 32, 32])
(32 + 2·1 − 3) / 1 + 1 = 32

עם kernel בגודל 3 וריפוד 1 הגודל נשמר. בלי ריפוד ועם צעד 2, אותה תמונה מתכווצת:

⌊(32 + 0 − 3) / 2⌋ + 1 = 14 + 1 = 15
שכבהמה עושהדוגמה
nn.MaxPool2d(2, 2)מקטינה את התמונה: מכל ריבוע 2×2 שומרת רק את הערך הגדול(4, 16, 32, 32) ל-(4, 16, 16, 16)
nn.BatchNorm2d(16)מנרמלת כל ערוץ לפי הממוצע וסטיית התקן שלו באצווה. מייצבת ומאיצה את האימוןלא משנה את הצורה

Dropout: כיבוי אקראי של נוירונים

באימון, Dropout מאפס כל ערך בהסתברות p, ומכפיל את הערכים ששרדו ב-1 / (1 − p), כדי שהממוצע יישאר זהה. כך הרשת לא יכולה להסתמך על נוירון אחד, וזה עוזר נגד overfitting. בהערכה הוא כבוי לגמרי.

1drop = nn.Dropout(p=0.5)2x = torch.ones(1, 6)3drop.train(); drop(x)    # e.g. [2., 2., 2., 2., 0., 2.]  (random)4drop.eval();  drop(x)    # [1., 1., 1., 1., 1., 1.]

עם p שווה 0.5, ערך ששרד מוכפל ב-2:

1 / (1 − 0.5) = 2

פונקציות Loss

Lossמתימה היא מצפה לקבל
nn.MSELossרגרסיהניבוי ותשובה, אותה צורה
nn.CrossEntropyLossסיווג לכמה מחלקותlogits גולמיים, ותגיות מסוג int64
nn.BCEWithLogitsLossסיווג בינאריlogit גולמי. הסיגמואיד כבר בפנים, בצורה יציבה מספרית

הבאג הנפוץ: Softmax כפול

CrossEntropyLoss כבר מפעילה Softmax בפנים. אם מוסיפים Softmax בסוף הרשת, הוא מופעל פעמיים והאימון נפגע. הרצנו את זה על logits של [2.0, 1.0, 0.1] עם מחלקה נכונה 0:

1ce = nn.CrossEntropyLoss()2logits = torch.tensor([[2.0, 1.0, 0.1]])3ce(logits, torch.tensor([0]))                   # 0.417  correct4ce(torch.softmax(logits, 1), torch.tensor([0])) # 0.802  wrong: softmax twice5ce(logits, torch.tensor([0.]))                  # error: target must be Long

אופטימייזרים ו-learning rate

opt_sgd  = optim.SGD(model.parameters(), lr=0.01, momentum=0.9)opt_adam = optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)

SGD עם מומנטום מצטיין בראייה ממוחשבת. AdamW הוא Adam עם weight decay נפרד, וזו ברירת המחדל לטרנספורמרים ול-LLM. optimizer.step() בא תמיד אחרי loss.backward().

Scheduler משנה את ה-learning rate במהלך האימון: צעדים גדולים בהתחלה וקטנים בסוף, כדי להתייצב ליד המינימום. נפוצים StepLR, CosineAnnealingLR ו-ReduceLROnPlateau. קוראים ל-scheduler.step() פעם בכל אפוק.

איך בוחרים learning rate (LR range test): מתחילים מ-10⁻⁶ ומגדילים פי 1.1 בכל צעד, עד בערך 10. מציירים את ה-Loss מול ה-learning rate, ובוחרים ערך קצת לפני המינימום של הגרף, איפה שהירידה הכי תלולה. זה הרעיון שמאחורי lr_find שראינו ב-fastai.

צינור הנתונים: Dataset ו-DataLoader

Dataset משלך צריך שלוש מתודות:

1from torch.utils.data import Dataset, DataLoader2class CustomDataset(Dataset):3def __init__(self, data, labels):    # store the data (or file paths)4self.data, self.labels = data, labels5def __len__(self):                   # how many examples6return len(self.data)7def __getitem__(self, idx):          # one example by index8return self.data[idx], self.labels[idx]9​10loader = DataLoader(dataset, batch_size=32, shuffle=True, num_workers=4)11for bx, by in loader:12...                                  # bx.shape: [32, features]

DataLoader עושה את כל מה שעשינו ביד: מחלק ל-mini-batches, מערבב את הסדר בכל אפוק, וטוען במקביל. לתמונות מוסיפים transforms: שינוי גודל, היפוך אקראי (augmentation), המרה לטנזור ונרמול. ToTensor() ממיר פיקסלים מ-0 עד 255 למספרים בין 0 ל-1.

לולאת האימון ולולאת ההערכה

1device = "cuda" if torch.cuda.is_available() else "cpu"2model = model.to(device)3​4for epoch in range(num_epochs):5model.train()                        # Dropout on, BatchNorm updates6for inputs, targets in train_loader:7inputs, targets = inputs.to(device), targets.to(device)8optimizer.zero_grad()            # 1. clear old gradients9outputs = model(inputs)          # 2. forward10loss = criterion(outputs, targets)   # 3. loss11loss.backward()                  # 4. gradients12optimizer.step()                 # 5. update13​14model.eval()                         # Dropout off, BatchNorm frozen15val_loss = 0.016with torch.no_grad():                # no graph, no backward17for inputs, targets in val_loader:18inputs, targets = inputs.to(device), targets.to(device)19loss = criterion(model(inputs), targets)20val_loss += loss.item() * inputs.size(0)

אלה בדיוק השלבים של הלולאה שכתבנו ממאפס בפרק אימון נוירון ממאפס (forward, loss, gradient, update), רק שעכשיו כל שלב הוא שורה אחת. הסדר המלא, כמו בשקף 52: train → to(device) → zero_grad → forward → loss → backward → step.
